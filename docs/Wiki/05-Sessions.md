# Blackbox 세션과 기록 계약

이 문서는 0.2.0의 세션, 수명, 동시성 및 출력 계약을 설명한다. 세션 하나는 하나의 기록 수명을 가진다. 0.1.x의 전역 출력 완료 상태와 `ToString()` 기반 객체 이름은 사용하지 않는다.

## 테스트 세션

```csharp
using var session = BlackboxHandle.BeginSession();
BlackboxHandle.Configure(logDirectory, Console.WriteLine,
    openLogOption: OpenLogOption.Never);
var system = new SystemUnderTest();
await system.RunAsync();
```

`BeginSession()`은 동기 메서드다. 세션 안에서 객체를 만들고, 자식 작업을 모두 await/join한 뒤 같은 논리적 범위에서 Dispose한다. 일반적인 Task와 Thread는 실행 문맥을 상속하지만 `ExecutionContext.SuppressFlow()`와 unsafe 큐잉은 상속하지 않는다. NUnit에서는 세션을 테스트 본문에서 열고, SetUp의 AsyncLocal 전파에 의존하지 않는다.

BlackboxSession은 SessionState, SubjectStore, 핸들 트래커와 세션 수명을 소유한다. SessionState는 설정·크래시·종료 여부·경고 표시·기록 카운터만 담는 데이터 객체다. 원자적 접근자 외의 정책이나 세션·저장소·트래커·레지스트리 참조를 갖지 않는다. 기록 코드(Blackbox, LogContext)는 소속 세션의 SessionState만 생성자로 주입받고 나머지 세션 구성 요소를 모른다. Exert·태그 대상 조회, Scope/Exert 핸들 등록과 출력은 세션을 함께 보관하는 BlackboxHandle이 맡는다. 태그는 BlackboxHandle이 세션을 묶어 준 TagHandle이 처리한다. 현재 세션 조회·흐름 바인딩·기본 세션 교체·활성 세션 추적은 내부 `BlackboxSessionRegistry`가 맡으며 공개 진단 API에는 세션 객체를 노출하지 않는다. SessionSettings는 설정을 복사한 뒤 원자적으로 교체하기 위한 별도 타입으로 유지한다.

현재 바인딩은 세션 참조만 보관한다. 중첩 세션을 닫으면 이전 바인딩으로 돌아간다. 이전 세션이 이미 종료되었다면 그 상태가 그대로 복원되며 기록은 거부된다. 다른 async 메서드에서 Dispose하면 그 메서드 안의 문맥만 복원된다. 세션 종료와 활성 목록 제거는 최초 Dispose에서만 수행한다. 바인딩 복원은 Dispose를 호출할 때마다 그 흐름이 이 세션에 묶여 있으면 시도한다. 따라서 다른 흐름이 먼저 종료했더라도 세션을 연 흐름은 자신의 Dispose로 이전 바인딩을 되찾는다.

`Of()`와 `Construct(out handle)`로 얻은 핸들은 생성 당시 세션에 고정된다. 다른 세션에서 사용해도 이동하지 않는다. 태그와 Exert 대상도 호출한 핸들의 저장소에서 조회한다. 세션을 넘나드는 객체의 스코프 자동 병합은 제공하지 않는다.

진단용 `BlackboxHandle.CurrentSessionKey`는 실행 문맥에 바인딩된 세션의 키이며, 바인딩이 없으면 `DefaultSessionKey`다. `BlackboxHandle.SessionKey`는 유효한 핸들이 고정된 세션 키이고 `IsValid == false`이면 `Guid.Empty`다. 세 속성은 읽기 전용 값만 반환하며 잠금·할당·경고 출력 없이 읽는다. 세션 객체를 반환하는 공개 Current API는 없다. 키는 세션의 기록 수명을 식별한다. 기본 세션을 재시작하면 DefaultSessionKey가 바뀐다. 종료된 명시적 세션의 문맥에서는 원래 키가 유지되지만 기록은 거부된다.

## 활성 세션 진단과 정리

`BlackboxSessionRegistry`는 잠금으로 보호하는 `List<BlackboxSession>` 하나에 활성 명시적 세션을 강하게 보관한다. Begin은 새 세션을 목록에 추가한 뒤 현재 흐름에 바인딩한다. 최초 Dispose가 핸들 ID를 회수하고 목록에서 제거한다. 기본 세션, 재시작으로 만든 새 기본 세션, 교체 경쟁에서 진 후보는 이 목록에 들어가지 않는다.

- `BlackboxHandle.ActiveSessionCount`: Dispose되지 않은 명시적 세션 수.
- `BlackboxHandle.GetActiveSessionKeys()`: 시작 순서의 `Guid[]` 스냅샷. 배열 수정은 내부 목록에 영향을 주지 않으며 세션 객체를 노출하지 않는다. 동시 Begin의 순서는 목록에 추가된 순서다.
- `BlackboxHandle.DisposeActiveSessions()`: 잠금 안에서 세션 스냅샷만 만들고, 잠금 밖에서 시작 역순으로 Dispose한다. 호출한 흐름의 활성 중첩 세션은 안쪽부터 닫혀 이전 바인딩이 복원된다. 다른 실행 흐름의 바인딩은 바꾸지 않으므로 그 흐름들은 종료된 세션에 남아 기록이 거부된다. 스냅샷 이후 시작한 세션은 대상에 포함되지 않는다.

Dispose를 잊은 세션은 참조를 버리고 GC를 실행해도 목록에 남으므로 누락을 진단할 수 있다. 정리하지 않으면 세션의 기록 상태와 미종료 Scope/Exert 핸들 ID를 프로세스 종료까지 유지한다. 세션은 테스트·디버그용이며 이 수명 비용을 의도적으로 받아들인다. 종료한 세션은 목록이 더 이상 보관하지 않지만 다른 핸들이나 실행 문맥이 참조하면 여전히 살아 있을 수 있다.

테스트 TearDown은 `ActiveSessionCount == 0`을 검사하고 실패 메시지에 남은 키를 넣은 뒤, `finally`에서 `DisposeActiveSessions()`로 정리한다. [README의 예시](../../README.ko.md#테스트-세션)를 참고한다. 전역 목록이므로 병렬 테스트에서는 다른 테스트의 세션도 보이고 일괄 정리가 그 세션을 종료할 수 있다. 전체 0 검사와 정리는 모든 작업을 await/join한 직렬 테스트 경계에서 사용한다. 개수와 키 조회는 각각의 스냅샷이므로 동시 시작·종료 중 두 호출의 결과가 같은 순간을 나타내지는 않는다.

## 기본 세션 재시작과 명시적 세션 종료

명시적 바인딩이 없는 코드는 공유 기본 세션을 사용한다. Of, Configure, RestartDefaultSession은 AsyncLocal 바인딩을 만들지 않는다. 따라서 기본 세션의 SetUp 설정은 이후 바인딩 없는 코드에도 보인다. 기본 세션을 변경하는 테스트는 직렬 실행한다.

`BlackboxHandle.RestartDefaultSession()`은 새 기본 세션을 먼저 생성하고 CAS로 공유 참조를 교체한 뒤 이전 세션을 Dispose한다. 교체 대상 기본 세션의 설정 스냅샷을 상속하고, 세션 키·파일 출력 일련번호·동결·경고·저장소·기록 카운터는 새로 시작한다. 경합에서 실패한 후보는 폐기하고 다시 시도한다. 기본 참조가 비어 있는 순간은 만들지 않는다. 동시 설정 변경까지 새 세션으로 반드시 전달하는 계약은 제공하지 않는다.

재시작은 호출 위치와 관계없이 기본 세션만 대상으로 한다. 명시적 세션 안에서 호출해도 해당 세션의 설정·핸들·자식 문맥은 유지되며, 마지막 명시적 세션을 닫으면 최신 기본 세션을 사용한다. 명시적 세션을 새로 시작하려면 Dispose 후 Begin을 호출한다. Begin은 그 시점의 현재 설정을 상속한다. 종료한 명시적 세션을 상속한 자식 문맥은 종료된 세션에 남고 기본 세션으로 자동 전환되지 않는다.

작업이 남은 상태에서 Dispose/RestartDefaultSession을 호출해도 기존 버퍼를 지우거나 새 세션에 재사용하지 않는다. 종료와 경합하는 기록은 이전 세션에서 완료되거나 생략될 수 있다. 종료와 핸들 등록이 겹치면 종료 쪽 또는 등록 쪽이 슬롯과 슬롯 세대를 담은 전체 ID로 반환한다. 슬롯 재사용 보호용 세대는 유지한다. 이 경쟁에 의한 새 세션 오염을 방지하지만 종료 순간의 완전한 로그 보존을 보장하지는 않는다.

## 객체 이름과 수명

```csharp
using var scope = BlackboxHandle.Of(this).Label(Name).Construct(out _bb);
```

자동 Subject `ToString()` 호출은 없다. 기본 표시는 `Monster #2`, 이름을 지정하면 `Forest (Monster #2)`다. `OwnerString`은 지정한 이름 또는 타입명을 반환한다. `Label(string)`은 같은 핸들을 반환하며 최초의 공백 아닌 이름만 저장한다. 같은 이름 재지정과 공백은 무시하고, 다른 이름 재지정은 최초 값 유지와 경고로 처리한다.

타입명은 네임스페이스를 생략하고 `List<Int32>`, `Outer<Int32>.Inner<String>`처럼 표시한다. 컴파일러 생성 이름은 원래 이름을 유지한다. HTML과 파일명에는 각각 맞는 이스케이프를 적용한다. 이름은 로그별 상태 이력이 아니라 객체 표시 메타데이터이며 출력당 한 번 확보한다. 현재 상태는 명시적 메시지로 기록한다. 호출자가 요청한 메시지 보간·오류 메시지 객체 포맷팅은 사용자 코드이므로 자동 이름 처리의 보장에 포함되지 않는다.

기본 Subject 참조는 약하다. 핸들은 Blackbox와 세션 상태를 유지하지만 Subject를 별도 필드로 강하게 붙잡지 않는다. Subject 수집 후에도 보관된 핸들로 이름과 로그를 읽거나 내보낼 수 있다. 기본 모드에서 Subject 자체가 Label과 같은 문자열 객체라면 별도 문자열로 복사한다.

`StrongReference` 모드는 Blackbox가 도달 가능한 동안 Subject도 강하게 유지한다. 직접 만든 저장소는 ConditionalWeakTable의 ephemeron과 다르므로, 기본 세션에서는 긴 수명을 가질 수 있다. Dispose는 기록 수명을 끝내며 보관된 참조의 즉시 GC를 뜻하지 않는다. Subject만 살아 있다는 이유로 과거 세션을 보관하는 인덱스는 없다.

## 동시성과 출력

세션 시작·종료와 활성 세션 조회는 활성 목록 잠금을 사용한다. 목록 스냅샷의 일괄 Dispose는 잠금 밖에서 수행한다. 이 동작은 테스트 경계의 수명 관리이며, `Write`, `Scope`, `Exert`, Subject 조회·등록을 포함한 기록·등록 경로는 계속 무잠금이다. `CurrentSessionKey`, `DefaultSessionKey`, 핸들의 `SessionKey` 조회도 활성 목록을 읽지 않아 잠금·할당이 없다.

Subject 저장소는 고정 버킷(명시적 세션 256, 기본 세션 65,536), 참조 동일성, 불변 노드와 CAS로 구현한다. 기본 세션의 버킷 배열은 64비트 환경에서 참조 영역 약 512KiB를 사용한다. 이미 등록된 Subject 조회에는 할당이 없으며 해시가 일치할 때만 Owner를 역참조한다. 미등록 Subject 삽입 경로에서 해당 버킷의 죽은 항목을 정리하고, 삽입 CAS가 성공하면 세션별 회전 커서로 추가 16개 버킷(테이블이 작으면 전체)을 정리 시도한다. 커서 구간은 Interlocked로 예약하며, 정리 CAS가 실패하면 재시도하지 않는다. 조회 적중 및 삽입 CAS 재시도에는 추가 회전 정리를 수행하지 않는다. 출력에서도 전체 버킷 정리를 시도한다.

기본 세션은 신규 삽입 4,096건마다 전체 버킷을 한 번씩 정리 시도한다. 이는 회수 성공이나 고정 메모리 상한을 뜻하지 않는다. GC 이후 신규 삽입이 멈추면 회전 정리도 멈추며, 기존 객체 조회만 계속되어도 마찬가지다. 남은 Blackbox의 컨텍스트마다 MaxLogCount 크기의 로그 참조 배열이 유지될 수 있다. 버킷에서 제거해도 보관된 핸들이나 다른 로그가 참조하는 Blackbox는 즉시 수집되지 않는다. 한 번에 보는 버킷 수는 제한하지만 체인 길이에 따른 정리 시간과 임시 할당량은 고정되지 않는다.

ThreadLocal 대신 스레드 토큰과 Blackbox별 불변 컨텍스트 목록을 사용한다. 토큰은 세션이나 Blackbox를 참조하지 않는다.

각 세션은 Scope/Exert용 트래커를 각각 16개씩 소유한다. 컨텍스트는 스레드 토큰 해시로 선택한 트래커를 공유하므로, 객체를 만들고 버리는 횟수에 따라 트래커가 누적되지 않는다. 추적 셀은 재사용하며, 동시에 보관하는 미반환 핸들이 많아지면 세그먼트가 늘 수 있다. 버려진 미종료 핸들의 ID는 세션 종료 때 회수한다. 트래커는 컨텍스트나 Subject를 참조하지 않는다. GC된 Subject의 저장소 노드 정리는 삽입 및 출력의 별도 작업이므로 GC 직후의 전체 힙과 트래커 잔류량은 구별한다.

링 버퍼에는 완성된 로그 값을 담은 불변 게시 객체를 저장한다. 태그와 병합도 객체 교체로 처리한다. 읽기는 슬롯의 논리 인덱스를 확인하며 늦은 게시가 새 기록을 덮어쓰지 못한다. 스코프 병합은 스코프 갱신이 성공한 뒤 상호작용 기록을 무효화한다. 변경된 로그는 전체 시퀀스로 정렬한 뒤 출력용 변환을 적용한다.

일반 `Export()`는 기록을 멈추지 않으며 반복할 수 있다. `CrashExport()`는 해당 세션의 최초 호출만 동결과 크래시 출력을 수행한다. 오류 메시지와 스택은 동결 정보에 함께 보관하므로 링 버퍼에서 밀려나지 않는다. 출력 실패 후에도 일반 Export로 다시 출력할 수 있으며 크래시 동결은 유지된다.

실행 중 출력은 근사 스냅샷이다. 미게시·덮어쓰기된 기록이 누락되거나 여러 컨텍스트에 걸친 상호작용의 일부만 보일 수 있다. 작업 종료 뒤에는 링 버퍼에 남아 있는 안정된 기록을 출력한다. 출력은 복사된 값만 변환하며 기록 원본을 수정하지 않는다. 시작 기록을 잃은 스코프도 음수 깊이를 만들지 않는다.

파일명은 타입명, Blackbox ID, 세션 키 앞 12자리, 출력 일련번호를 포함한다. 새 파일 생성 모드로 충돌을 확인하고 재시도하므로 기존 파일을 덮어쓰지 않는다. 파일 누적 정리는 호출자가 담당한다.

내부 기록·최초 등록 경로는 잠금 없이 CAS/Volatile/Interlocked를 사용한다. 런타임·GC·할당·I/O·외부 콜백 자체의 동기화는 별개다. 불변 로그 게시에는 기록당 할당이 필요하며 전체 기록 경로가 무할당이거나 wait-free라고 주장하지 않는다.

종료된 세션의 핸들, 다른 스레드에서 닫히는 Scope/Exert 등의 경고는 세션별·원인별 최초 1회다. 원자적 플래그를 먼저 선점한 뒤 로거를 호출한다. 세션 자체는 await 이후 스레드가 바뀌었다는 이유로 경고하지 않는다.

## 검증

Release NUnit 테스트는 일반 시나리오 외에 등록 경쟁, 강제 지연 게시, 종료 중 슬롯 등록, 기본 세션 재시작과 명시적 세션 격리, 경고 재진입, 약한 참조 수명, 출력 실패와 링 버퍼 순환을 검증한다. 기본 구성과 `-p:BlackboxLockHandles=true` 비교 구성을 구분한다. 잠금 비교 구성에는 무잠금 보장이 적용되지 않는다.

성능 측정 방법과 변경 전후 수치는 [벤치마크](../../benchmarks/README.md)를 참고한다. 테스트 호스트 연결 실패는 통과가 아니다.
